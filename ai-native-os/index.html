The Problem

AI coding is powerful. And quietly fragile.

One-off agent prompts work. Chains of them, across sessions and tasks, without guardrails? That is how quality silently erodes.

🔁

No separation of concerns

The same agent that builds your feature also reviews it. No adversarial check, no second opinion. Just confirmation bias at machine speed.

📭

Decisions vanish

The "why" behind architecture choices, tradeoffs accepted, constraints imposed. Gone after the session ends. Future agents inherit the what, never the why.

💡

Ideas skip validation

Raw ideas go straight to implementation with no stress test. Nobody asks who the customer is, why now, or what kills it. The Skeptic never gets a turn.

🎲

Failures don't patch the system

Every incident is a one-time lesson. Nothing updates the prompt that caused it. The system has no memory of what went wrong or how to prevent recurrence.

The Two Flows

Structured from first thought to shipped PR.

Two end-to-end flows, each with role separation enforced at every stage and a governance checkpoint before you proceed.

Adversarial ideation loop

Visionary owns problem framing, user value, and strategic direction. Skeptic stress-tests go-to-market reality, competition, and monetization. The loop runs until Skeptic status is ALIGNED and a task list is produced. No idea leaves unclassified: STRONG_SIGNAL, NEEDS_SHARPENING, or PARK_FOR_NOW.

Governance

Reviews the task list. Loops until approved. CTO runs a feasibility sniff on every task before the list is handed to you.

Flow 2
plan-to-build-flow

1

Generate the execution orchestration prompt

Takes a single approved task and produces a task-specific execution prompt, with standing invariants baked in and CTO review modes selected for the task type.

G
Governance

Reviews the prompt. Verifies all standing invariants are present and unmodified. Loops until approved.

2
Builder CTO

Adversarial build loop

Builder implements. CTO reviews independently across Architecture, Security, Data Integrity, Operability, and Reliability. CTO issues blockers. Builder fixes them. The loop continues until CTO status is APPROVED with no open blockers. A decision record is produced for every task.

G
Governance

Reviews the PR and session report. Verifies all standing invariants hold across the full diff, decision record is complete, and alignment log documents every round. Loops until approved.

🔒

Output is PR READY FOR HUMAN PUSH. You review and push. No automated force push, no destructive git operations without your sign-off.

The Four Roles

Role separation enforced, not suggested.

Each role has a fixed lens and fixed ownership. No role collapses into another. No Orchestrator editing implementation files. No Builder declaring its own review passed.

Visionary
Lens: CEO / CPO

Owns problem framing, user value, and strategic direction. Must answer: what is the 10x opportunity, what are the riskiest assumptions, and why is this defensible.

Skeptic
Lens: CSO / CMO

Owns go-to-market reality, competitive differentiation, and monetization path. Stress-tests until hardened or correctly discarded. Must reach ALIGNED status to proceed.

Builder
Lens: Engineer

Implements code within task scope. Cannot collapse into Orchestrator. Mandated to follow all seven standing invariants on every task, no exceptions.

CTO
Lens: Chief Technical Reviewer

Adversarial reviewer. Reviews the full diff independently. Issues blockers Builder must fix. Must reach APPROVED status with no open blockers before the PR is handed back.

Sneak Peek

What is inside

Five templates power both flows. Each is a structured prompt with hard-stop rules, role separation enforced, and governance checkpoints built in.

Template Ideation Prompt Generator

Takes a raw idea and generates the ideation orchestration prompt, tailored to the idea category and the right Skeptic focus areas.

Template Ideation Orchestrator

Runs the Visionary / Skeptic loop. Produces a validated problem statement, ambition classification, and a CTO-sniffed task list.

Template Orchestration Prompt Generator

Takes an approved task and generates the execution orchestration prompt with standing invariants and CTO review modes locked in.

Template Orchestrator (Builder/CTO)

Runs the Builder / CTO adversarial loop. Outputs a reviewed PR and a complete decision record with alignment log for every round.

Template System Retrospective

Reviews completed runs, classifies failures, and recommends patches to the template that allowed the failure. The OS learns from every build cycle.

Invariants 7 Standing Hard Blocks

Event-loop safety, fail-closed, no silent caps, additive-only migrations, frozen tool contracts, docs in the same PR, and a real-infra gate for async changes. Non-debatable architectural law baked into every task.
