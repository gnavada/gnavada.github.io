The Problem

AI coding is powerful — and quietly fragile

One-off agent prompts work. Chains of them, across days and teammates, without guardrails? That's how quality silently erodes.

🔁

No separation of concerns

The same agent that builds your feature also reviews it. There's no adversarial check, no second opinion — just confirmation bias at machine speed.

📭

Decisions vanish

The "why" behind architecture choices, tradeoffs accepted, constraints imposed — gone after the session ends. Future agents (and humans) inherit the what, never the why.

📈

Doesn't scale past one

Prompting one feature works. Coordinating 10 tasks across sessions, with consistency and no regression? There's no operating model for that.

🎲

Templates don't learn

Every failure is a one-time lesson. Nothing patches the prompt that caused it. The system has no memory of what went wrong or how to prevent recurrence.

System Memory
1

Idea → Plan (structured template)

Every initiative starts from a canonical template — goals, constraints, acceptance criteria, and risk flags captured before a single line of code is touched.

2

Builder/CTO adversarial split

The agent that implements never reviews. A separate CTO-role agent reads the plan and the output independently — no shared context, no soft-ball review.

3

Decision records — always

Every non-trivial choice produces a decision record: option considered, constraint that decided it, tradeoff accepted. Future sessions inherit the reasoning, not just the result.

4

Retrospectives that patch the system

When something fails, the retrospective classifies the failure and patches the template that allowed it. The OS gets smarter with every build cycle.

Sneak Peek

What's inside

A look at the templates and flows — without giving away the exact prompt engineering that makes them work.

Template Idea Capture

Structured intake for any new feature or initiative. Forces clarity on goals, constraints, and success criteria before any agent touches code.

Template Build Plan

Breaks a plan into atomic, reviewable tasks. Each task has a scope boundary so the Builder can't silently expand work.

Template CTO Review

A role-anchored review prompt that confronts the output as an independent technical leader — not a yes-man.

Template Decision Record

Lightweight ADR format. Captures option, chosen path, reasoning, and constraints — in one structured block per decision.

Template Retrospective

Post-build failure classification and template patch log. Turns each incident into a durable system improvement.

Flow Idea → Plan → Build

End-to-end chain that sequences templates automatically. Run the flow, get a production-ready task list with review checkpoints baked in.
